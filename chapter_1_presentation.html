The Problem: Store 10,000 Images

A dataset of 10,000 grayscale images, each 28 by 28 pixels, has 7,840,000 scalar values.

Naive Python representation

images = [
    [[pixel(img, row, col) for col in range(28)]
     for row in range(28)]
    for img in range(10000)
]

Why this is expensive

  • Python lists store pointers, not raw numbers.
  • Each Python float carries object overhead.
  • Accessing one pixel requires several pointer dereferences.
  • The CPU sees scattered objects instead of one dense numeric buffer.
Teaching moveDo not start with formulas. Start with the pain: students already understand a list of images. Then show why the natural representation is the wrong physical representation.

The Core Solution

Store only the numeric values in one flat buffer. Store the multidimensional meaning separately as metadata.

Storage

One flat array of values in memory.

Shape

How many positions exist along each axis.

Strides

How far to jump in storage when one logical index changes.

Offset

Where this view begins inside the shared storage.

Tensor view = storage + shape + strides + offset + dtype
Key sentence for students: a tensor is not "a grid in memory"; it is a rule for interpreting flat memory as a grid.

The Flat Index Formula

Every logical coordinate maps to one physical storage position.

I(i) = O_base + sum over k of i_k * d_k

Symbols

  • I(i): flat storage index.
  • O_base: base offset of the view.
  • i_k: logical index on axis k.
  • d_k: stride on axis k.

Meaning

Start at the view's offset. For every axis, multiply the logical coordinate by that axis's stride. Add the jumps.

Student check: For shape (3,4), strides (4,1), offset 0, compute I(2,1). Answer: 2*4 + 1*1 = 9.

Strides

shape = (3, 4)
strides = (4, 1)
  • Move one row down: jump 4 storage positions.
  • Move one column right: jump 1 storage position.
  • Rows are cache-friendly.
C-order recursive rule: d_last = 1, and d_k = shape[k+1] * d_{k+1}

F-Contiguous Layout

Fortran-order, also called column-major layout, stores columns contiguously. The first axis varies fastest.

Same logical matrix

Nothing changes about the mathematical matrix. Only the storage order changes.

shape = (3, 4)
strides = (1, 3)

Interpretation

  • Move one row down: jump 1 storage position.
  • Move one column right: jump 3 storage positions.
  • Columns are cache-friendly.
LayoutStride pattern for (3,4)Fast traversalCommon ecosystem
C-order(4, 1)RowsC, NumPy default, PyTorch default
F-order(1, 3)ColumnsFORTRAN, MATLAB, BLAS/LAPACK heritage

Worked Example: 3D C-Order Strides

For shape (3, 4, 5), compute C-contiguous strides from right to left.

Stride derivation

d_2 = 1
d_1 = shape[2] * d_2 = 5 * 1 = 5
d_0 = shape[1] * d_1 = 4 * 5 = 20

Flat index

I(2,1,3) = 0 + 2*20 + 1*5 + 3*1
I(2,1,3) = 48
Ask students: For the same shape, what are F-order strides? Answer: (1, 3, 12).

Slicing Is Metadata Transformation

A slice usually does not copy data. It creates a new view with new metadata.

Original

shape = (3, 4)
strides = (4, 1)
offset = 0

Slice: T[1:, 1:]

shape = (2, 3)
strides = (4, 1)
offset = 1*4 + 1*1 = 5
The storage buffer is unchanged. The view simply starts at flat position 5 and accepts a smaller coordinate range.
Common misconceptionMany students assume slices are independent arrays. Demonstrate with mutation: modifying a view can modify the original when storage is shared.

General Slice Rule

A slice along axis k has start, stop, and step. The view coordinate maps back to the original coordinate by an affine rule.

i_k = start_k + j_k * step_k

New offset

O'_base = O_base + sum(start_k * d_k)

New strides

d'_k = step_k * d_k
Practice: Original shape (10,10), strides (10,1). Slice T[1:5:2, ::-1]. Result: shape (2,10), strides (20,-1), offset 19.

Transpose Is a Stride Permutation

For a 2D matrix, transpose swaps the axes. That means shape and strides swap. The storage buffer stays fixed.

Before

shape = (3, 4)
strides = (4, 1)
offset = 0

After T.T

shape = (4, 3)
strides = (1, 4)
offset = 0
This is why transposing a huge tensor can be nearly instant: the framework creates a new view object instead of moving all values.
But the transposed view may be non-contiguous for the next operation. Zero-copy does not always mean fast to traverse.

Reshape: When Is It Free?

Reshape is zero-copy only when the existing memory layout can be reinterpreted consistently under the new shape.

Usually free

  • Tensor is contiguous.
  • New shape has same volume.
  • Existing storage order matches the requested interpretation.

Requires copy

  • Tensor is a non-contiguous slice.
  • Tensor was transposed and then flattened.
  • Strides cannot describe the new logical layout.
# PyTorch distinction
y = x.view(new_shape)      # requires compatible contiguous-like layout
y = x.reshape(new_shape)   # returns a view if possible, otherwise copies

Quick calculation: How much memory for a (10000, 28, 28) float32 tensor? 7,840,000 * 4 = 31,360,000 bytes, about 31.36 MB.

Why Strides Affect Speed

CPUs fetch memory in cache lines, not one value at a time. A typical cache line is 64 bytes.

float32 cache line

64 bytes / 4 bytes = 16 float32 values

If you access values contiguously, one miss brings the next 15 values along with it.

Large stride

If each next value is more than one cache line away, almost every access is a miss.

stride >= 16 float32 elements -> poor spatial locality
AnalogyThe cache line is like receiving 16 nearby lockers whenever you request one locker. Sequential access uses the delivery well; large-stride access throws most of it away.

AMAT: A Simple Cost Model

Average Memory Access Time estimates the cost of memory access from hit time and miss rate.

AMAT = T_hit + miss_rate * T_penalty

Contiguous float32 access

miss_rate = 1/16 = 0.0625
AMAT = 1 ns + 0.0625 * 100 ns
AMAT = 7.25 ns

Cache-thrashing access

miss_rate = 1.0
AMAT = 1 ns + 1.0 * 100 ns
AMAT = 101 ns
The exact constants are simplified for teaching. The direction is the important point: bad memory access patterns can dominate arithmetic.

View vs Copy Trade-off

A view is cheap to create. A copy is expensive upfront but can make later reads faster.

OperationTouches data?Time ideaWhen useful
Slice viewNoO(rank)Inspect, pass around, light use
Transpose viewNoO(rank)Change logical axes cheaply
Contiguous copyYesO(volume)Hot loop, matrix multiply, repeated traversal
Practical rule: if a non-contiguous view will be traversed repeatedly in a performance-critical operation, making it contiguous may be worth the copy.

GPU Memory Hierarchy

GPUs have the same fundamental problem: moving data is often more limiting than doing arithmetic.

Registers

Fastest, per thread.

Shared / L1

Fast, per streaming multiprocessor.

L2 Cache

Shared across the GPU.

HBM

Large global GPU memory, slower than on-chip memory.

Arithmetic intensity = FLOPs / bytes read
Bridge to later chaptersTell students this is why fused kernels, FlashAttention, and optimized matrix multiplication matter. They reduce expensive memory traffic.

Implementation: Minimal Strided Tensor

The teaching implementation stores a Python list as storage and manually tracks shape, strides, and offset.

class FlatArray:
    def __init__(self, shape, values=None, storage=None,
                 strides=None, offset=0):
        self.shape = tuple(shape)
        self.strides = strides or row_major_strides(shape)
        self.offset = offset
        self.storage = storage if storage is not None else list(values)

    def flat_offset(self, indices):
        return self.offset + sum(
            i * d for i, d in zip(indices, self.strides)
        )
The code is short because the core idea is simple: every access is offset arithmetic followed by a storage lookup.

Implementation Walkthrough

Construction

  • Validate shape.
  • Compute default row-major strides.
  • Store or share a flat buffer.
  • Validate reachable offsets.

Indexing

  • Integer index consumes an axis.
  • Slice keeps an axis but changes shape, stride, offset.
  • None inserts an axis with stride 0.
  • Ellipsis expands omitted axes.
Live coding prompt: Implement row_major_strides((3,4,5)) and test that it returns (20,5,1).

Common Student Mistakes

Concept mistakes

  • Thinking a slice always copies data.
  • Thinking transpose physically rearranges values.
  • Confusing logical shape with physical storage order.
  • Ignoring dtype when computing memory footprint.

Math/code mistakes

  • Using the wrong stride formula for C-order.
  • Forgetting offset when indexing a view.
  • Handling negative strides incorrectly.
  • Calling reshape and assuming it is always free.
Most bugs come from forgetting that a view's logical element (0,0) may not live at physical storage position 0.

Chapter Summary

Conceptual takeaways

  • A tensor is flat storage plus metadata.
  • Shape describes valid logical coordinates.
  • Strides translate coordinate movement into storage movement.
  • Offset allows views to start inside shared storage.

Engineering takeaways

  • Slicing and transpose are often metadata-only.
  • Reshape is free only when layout permits it.
  • Bad strides can waste cache lines and memory bandwidth.
  • PyTorch and NumPy are built on this model.
The formula to remember: flat_index = offset + sum(index_k * stride_k)
